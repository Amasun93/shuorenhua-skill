# 说人话｜专业概念解释 Skill

让陌生知识接上生活经验。

“说人话”是一个面向普通读者的专业知识翻译官。它不只是把术语换成口语，也不只是削弱 AI 味道，而是先找到一个熟悉的生活场景，再把专业概念放进去，让人看懂它是什么、为什么存在、怎样运转，以及它对自己的影响。

## 安装

使用 Skills CLI：

```bash
npx skills add Amasun93/professional-explainer-zh
```

手动安装：

```bash
git clone https://github.com/Amasun93/professional-explainer-zh.git
```

然后将仓库中的 `SKILL.md` 放入你的 Agent Skills 目录。

## 怎么用

安装后，可以直接这样提问：

```text
用说人话解释一下 GitHub 里的仓库、分支和 Pull Request。
```

```text
把 Render、腾讯云和阿里云的区别讲得像几家物业公司。
```

```text
我不懂 MCP，请先用一个生活场景讲清楚，再告诉我每个术语对应什么。
```

```text
解释一下 RAG，要求简短、生活化，并告诉我它可能出什么问题。
```

## 它的核心方法

### 先生活地图，再专业揭晓

如果要解释一组相关概念，不会一上来堆术语，而是先讲一个完整的生活场景：

> 几个人一起经营一家店。正式账本放在总店里；有人想试做新菜单，就先拿副本单独修改；确认没问题后，再提交给大家检查，最后放回正式账本。

然后再对应：

| 生活场景 | GitHub 概念 | 作用 |
|---|---|---|
| 总店和完整账本 | 仓库 Repository | 保存项目文件和历史版本 |
| 给账本盖章 | 提交 Commit | 保存一次阶段性修改 |
| 拿副本试做新菜单 | 分支 Branch | 隔离修改，不影响正式版本 |
| 提交给大家检查 | Pull Request | 请求把修改合并进正式版本 |

这样读者先看懂“店是怎么经营的”，再认识专业词。

### 信、达、活

- **信**：不改变原意，不漏掉条件、限制、数字、风险和不确定性。
- **达**：让读者真正建立认知连接，不只是替换术语。
- **活**：使用生活中的人物、动作和关系；必要时加入轻松幽默或网络梗帮助记忆。

类比是桥梁，不是定义本身。需要时会补充专业定义或事实校准；不需要时不会为了完整而堆固定模块。

## 适合什么问题

- 解释陌生的技术或专业术语；
- 解释一组术语如何配合；
- 比较云服务、工具或方案；
- 把功能和使用流程讲给没有专业背景的人；
- 解释报错、故障和限制为什么会出现。

## 不适合什么问题

- 单纯去 AI 味、润色或改写中文；
- 逐字翻译，并且要求保留原文风格；
- 只需要一个准确的专业定义，不需要生活化解释；
- 主要内容是代码、日志、命令或配置本身。

## 联网与事实

默认先解释用户提供的材料。遇到资料不足、价格和政策等可能变化的事实，或用户明确要求核验时，再查找资料；动态信息优先使用官方来源。

生活类比、专业定义和外部事实会分开表达，避免把比喻当成事实。

当前版本：`0.1.0`

这是第一版可用稿，重点验证“生活地图 → 术语揭晓 → 直接判断”的解释方式。后续会根据真实使用反馈继续调整，而不是把所有回答固定成同一个模板。
