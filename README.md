# 说人话｜专业概念解释 Skill

> 把陌生知识讲到“原来如此”。

“说人话”是一个面向所有专业领域的知识翻译官。它不只是把术语换成口语，也不只是削弱 AI 味道，而是先找到一个读者熟悉的生活场景，再把专业概念放进去，让人看懂它是什么、为什么存在、怎样运转，以及它对自己的影响。

它可以解释技术，也可以解释医学、法律、金融、科学、教育、工程、商业和其他专业知识。技术只是其中一个使用场景。

## 安装

把下面这段提示词发送给你的 AI，它会帮你安装这个 Skill，并告诉你安装后怎么使用：

```text
请帮我安装这个 Skill，并告诉我安装后怎么使用：
https://github.com/Amasun93/professional-explainer-zh
```

## 怎么用

安装后，直接把你看不懂的内容交给它：

```text
请用“说人话”解释一下 GitHub 里的仓库、分支和 Pull Request。
```

```text
请用生活中的例子解释“复利”，让我知道它为什么会越滚越快。
```

```text
我不懂劳动合同里的“竞业限制”，请先用一个生活场景讲清楚，再告诉我这个词在法律上是什么意思。
```

```text
请解释一下免疫系统：先让我知道它要解决什么问题，再说明抗体、抗原和免疫记忆之间的关系。
```

你也可以指定表达方式：

```text
用一个统一的生活场景解释这些术语，先讲故事，再给我对应表。不要写得像教科书。
```

## 它怎么把专业知识讲明白

它通常会经历这样一条认知路径：

> 找到熟悉经验 → 搭建生活场景 → 让场景运行起来 → 揭晓术语对应关系 → 补充关键事实 → 给出实际影响或下一步

比如解释 GitHub 时，不会一上来解释一堆英文词，而是先讲：

> 几个人一起经营一家店。正式账本放在总店里；有人想试做新菜单，就先拿一份副本单独修改；确认没问题后，再提交给大家检查，最后放回正式账本。

然后再对应：

| 生活场景 | GitHub 概念 | 作用 |
|---|---|---|
| 总店和完整账本 | 仓库 Repository | 保存项目文件和历史版本 |
| 给账本盖章 | 提交 Commit | 保存一次阶段性修改 |
| 拿副本试做新菜单 | 分支 Branch | 隔离修改，不影响正式版本 |
| 提交给大家检查 | Pull Request | 请求把修改合并进正式版本 |

这样，读者先看懂“店是怎么经营的”，再认识专业词。

## 适合解释什么

| 类型 | 可以怎么问 |
|---|---|
| 技术与 AI | API、MCP、GitHub、RAG、数据库、部署 |
| 医学与生命科学 | 免疫系统、疫苗、基因、代谢、临床试验 |
| 法律与制度 | 竞业限制、知识产权、合同条款、行政许可 |
| 金融与经济 | 复利、通货膨胀、基金、现金流、机会成本 |
| 科学与工程 | 相对论、芯片、机械结构、能源、材料 |
| 教育与社会科学 | 课程设计、心理学概念、社会制度、研究方法 |
| 产品与商业 | 商业模式、用户增长、供应链、定价、运营指标 |

它尤其适合下面几类问题：

- “这个词到底是什么意思？”
- “为什么会有这个东西？”
- “它解决了什么问题？”
- “这些术语之间是什么关系？”
- “几个方案到底有什么区别？”
- “我实际遇到它时应该怎么理解或选择？”

## 核心理念：信、达、活

- **信**：不改变原意，不漏掉关键条件、限制、数字、风险和不确定性。
- **达**：让读者真正建立认知连接，而不是只把一个术语替换成另一组术语。
- **活**：使用生活中的人物、场所、动作和关系；必要时加入轻松幽默或网络梗帮助记忆。

类比是桥梁，不是正式定义。需要时会补充专业定义或事实校准；不需要时不会为了完整而堆固定模块。

## 它不会怎么做

- 不把所有专业词机械替换成生活词；
- 不在同一个解释里混用多个互不相干的比喻世界；
- 不为了“说得简单”而删掉关键条件和风险；
- 不把网络梗当成正式定义；
- 不把生活类比冒充医学、法律、金融等领域的正式意见；
- 不把单纯的中文润色或去 AI 味，误当成专业概念解释。

## 联网与事实

默认先解释你提供的材料。资料不足、价格和政策等事实可能变化，或你明确要求核验时，再查找资料；动态信息优先使用官方来源。

涉及医学、法律、金融等高风险领域时，它负责帮助你建立基本理解，不替代具备资质的专业人士给出最终诊断、法律意见或投资决策。
